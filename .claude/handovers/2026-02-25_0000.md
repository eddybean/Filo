- `copy_and_verify` は `platform_copy` に委譲するよう変更

## 決定事項

- **`copy_and_verify` のサイズ検証**: コピー前の fresh `fs::metadata` を省略し、列挙フェーズのキャッシュ値（`pending.file_size`）を使う。TOCTOU の窓はわずかに広がるが、Filo のユースケース（整理対象ファイルが別プロセスに書き換えられる可能性は極めて低い）では許容できると判断
- **`COPY_FILE_REQUEST_COMPRESSED_TRAFFIC` のみ使用**: `COPY_FILE_NO_BUFFERING` はセクタサイズ境界の整合要件があり複雑なため不採用
- **フェーズ2（Rayon 並列化）は今回見送り**: ローカル SSD + 少数ファイルでは逆効果の可能性があるため、フェーズ1・3の効果測定後に判断
- **`fs::rename` の改善は不要**: 同一デバイス rename はデータコピーのない純粋なメタデータ操作であり、改善余地がない

---

## 捨てた選択肢と理由

| 選択肢 | 不採用理由 |
|---|---|
| `COPY_FILE_NO_BUFFERING` | ファイルサイズがセクタサイズの倍数でない場合に失敗する。ネットワークドライブでの改善も限定的 |
| Rayon による並列ファイル処理 | 単一 SSD・少数ファイルでは効果が小さいかむしろ遅くなる可能性。キャンセル処理との統合も複雑化する |
| Windows `IFileOperation` COM | 実装コストが極めて高い割に CopyFile2 との差が不明瞭 |
| CopyFile2 でのネイティブキャンセルコールバック | `pfCancel: *mut BOOL` のみで十分。コールバックは実装が複雑 |

## ハマりどころ

- **スロットリングの初回スキップ問題**: `last_progress_emit = Instant::now()` で初期化すると最初のファイル処理時に 100ms 経過していないためコールバックが呼ばれず、`test_cancel_skips_remaining_files` が失敗。`Option<Instant>` に変更して `None` のとき初回として常に送信することで解決
- **`undo_file_move` の呼び出し見落とし**: `move_file` のシグネチャ変更後に `undo_file_move` 内の呼び出し箇所を更新し忘れてコンパイルエラー。`fs::metadata(destination_path).map(|m| m.len()).unwrap_or(0)` で対応

## 学び

- **`std::fs::copy` on Windows は `CopyFileExW` を使う（`CopyFile2` ではない）**: Rust stdlib は互換性重視で dwCopyFlags=0 のフラグなしで呼ぶ。`CopyFile2` に切り替えると `COPY_FILE_REQUEST_COMPRESSED_TRAFFIC` が使える
- **`COPY_FILE_REQUEST_COMPRESSED_TRAFFIC` はフォールバック保証あり**: SMB サーバーが非対応の場合は無視されて通常コピーになる。エラーにはならない
- **ローカル → ネットワークドライブの移動は常に cross-device**: `rename` が `CrossesDevices` エラーで失敗し、`copy_and_verify + remove_file` にフォールバックするため CopyFile2 の改善が確実に適用される
- **SMB サーバーサイドコピー（FSCTL_SRV_COPYCHUNK）は CopyFile2 だけでは有効にならない**: ソースがローカルの場合は適用不可。Explorer の速さは IFileOperation 経由の並列処理・バッファリング戦略によるものと推察
